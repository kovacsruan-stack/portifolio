# GitHub Organization Strategy

## Objetivo

Organizar o GitHub para que um recrutador consiga entender o perfil em poucos minutos.

## Ordem recomendada

1. portifolio — índice profissional
2. kovi-ai — IA e arquitetura
3. kovian-fitness — backend/full stack
4. kovian-finance — domínio financeiro
5. kovian — ecossistema
6. Projetos menores e acadêmicos

## Público

Pode conter documentação, README, diagramas, testes, exemplos sanitizados, código sem segredos e projetos demonstrativos.

## Privado

Manter privado quando houver credenciais, dados reais, integrações sensíveis, infraestrutura interna ou código ainda não preparado para publicação.

## Regra de primeira impressão

Cada repositório público relevante deve ter descrição objetiva, README, stack, problema, funcionalidades, arquitetura, execução, testes, segurança, limitações, roadmap e screenshots/demo quando possível.

## Evitar

Repositórios vazios, nomes genéricos, README superficial, secrets, dumps, credenciais, afirmações de produção não verificadas e excesso de projetos incompletos sem contexto.

## Estratégia

Poucos projetos bem documentados demonstram melhor evolução profissional do que muitos repositórios sem contexto.
